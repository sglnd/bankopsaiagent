# 变更影响分析

## 目标

基于变更、CMDB、告警、日志、性能指标和历史事件的实际证据，识别直接影响、间接影响、资源风险、业务风险和实施窗口风险。不得用常识补齐缺失的生产数据。

## 输入与默认范围

- 从用户输入中提取变更单号；缺少编号时再请求用户提供。
- 以变更系统记录为事实入口。目标 CI、系统标识、实施窗口、验证和回退方案必须来自工具结果，不得根据名称或经验猜测。
- 默认分析变更前 7 天的告警和变更前 24 小时的性能；用户指定窗口时以用户要求为准，并在报告中写明实际窗口。

## 能力边界

- ChangeInfo MCP：变更主数据和历史相似变更；不提供 CMDB、告警或性能事实。
- CMDB MCP：配置项、上下游关系及网络路径；输入 CI 必须来自变更或已返回的拓扑。
- AlertInfo MCP：告警、日志异常和历史生产事件。
- PerfInfo MCP：性能指标目录、窗口汇总和原始采样。
- Knowledge MCP：制度、操作手册和历史经验；知识内容只能作为控制要求或辅助判断，不能代替实时生产事实。

只使用当前已加载且模型可见的工具。根据工具描述和输入 Schema 自主选择具体方法，不在 Skill 中假设未加载的方法存在。优先选择能够以最少调用获得充分证据的工具，并复用已经取得的有效结果。

## 调查策略

1. 取得并核验变更事实，确认变更类型、对象、范围、窗口、步骤、验证和回退条件。
2. 使用 CMDB 能力展开目标对象的直接依赖和关键间接依赖。应用发布重点调查应用模块、部署实例、主机、数据库、中间件和上下游；防火墙开通重点调查源/目标 CI、安全域、IP、协议、端口、路径设备和策略边界。
3. 根据拓扑、重要度和变更内容筛选关键 CI，再调查它们的近期告警、错误事件、性能和容量；不要无差别查询所有外围对象。
4. 调查同系统、同类型的历史变更和相关故障，判断控制措施是否覆盖已知失败模式。
5. 对跨来源事实进行核对，记录冲突、失败、空结果和覆盖不足；使用 [risk-rules.md](references/risk-rules.md) 分级，并按 [output-template.md](references/output-template.md) 输出。

## 工具选择规则

- 先发现目标 CI 实际存在的指标，再查询相关汇总或采样；不得猜测指标名。
- 先使用汇总能力识别异常，只有在需要判断趋势、持续性或峰值时才查询原始明细。
- 工具返回成功但结果为空时，记录“查询无结果”和查询范围；不得将其解释为系统正常。
- 只对明确的瞬时错误重试一次；参数错误、权限拒绝和确定性空结果不得盲目重试。
- 相同工具、参数和时间窗口已有有效结果时不得重复调用。
- 达到完成条件或已确认剩余证据不可获得时停止调查，避免为了形式完整持续消耗 Token。
- 涉及审批状态或生产操作的结论必须来自权威系统工具；Skill 不得批准变更或执行生产操作。

## 必需证据

给出最终结论前必须覆盖下列证据域，或明确说明该域无法取得数据及其对结论的影响：

- 变更内容与实施窗口
- 直接系统与上下游依赖
- 主机、数据库和中间件资源
- 近期告警和错误日志
- 关键性能指标
- 历史类似变更或故障

## 证据规则

- 每项风险依据必须注明来源域、实际工具、关键查询范围及返回事实。
- 清楚区分“已观测事实”“基于事实的推断”和“数据缺口”。
- 工具无数据、超时或报错不等于系统正常。
- 不得虚构指标值、依赖关系、历史事件或审批状态。
- 数据不足以判断时，输出“暂无法定级”，并列出补数清单；不能为了完成格式而猜测等级。

## 完成条件

最终答案必须包含风险等级、风险依据、影响范围、数据缺口和行动建议。每个重要结论都能追溯到工具证据或被明确标记为推断；仅输出“高/中/低风险”不算完成。
