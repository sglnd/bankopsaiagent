# 风险分级规则

风险判断采用证据优先原则，不做简单平均。

## 高风险

满足任一强风险条件，或多个中风险条件形成同一故障链：

- 涉及核心交易、账务或支付链路，且缺少有效隔离或回退证据。
- 数据库、连接池、磁盘或关键主机已接近容量边界。
- 近期存在与变更对象相关的严重告警、错误日志或性能恶化。
- 历史类似变更曾引发故障，且本次未提供针对性控制措施。
- 多个关键上下游会被同时影响，可能造成业务级联中断。

## 中风险

- 存在关键依赖，但已有可验证的隔离、灰度或回退措施。
- 资源余量尚可，但部分指标接近预警线或趋势持续恶化。
- 存在告警或历史异常，但与当前变更的关联度尚不确定。
- 影响面有限，但实施窗口、验证方案或监控覆盖不完整。

## 低风险

只有在证据完整时才能判定低风险：影响范围有限、无关键上下游、资源余量充足、近期无相关异常，并且回退与验证方案明确。

## 数据不足

关键证据域缺失时不得判为低风险。若缺失项足以改变风险结论，使用“暂无法定级”；若仍可由其他强证据确定高风险，可以定为高风险，同时显著披露缺口。
