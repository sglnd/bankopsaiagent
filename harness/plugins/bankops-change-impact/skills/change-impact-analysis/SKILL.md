# 变更影响分析

## 目标

基于变更、CMDB、告警、日志、性能指标和历史事件的实际证据，识别直接影响、间接影响、资源风险、业务风险和实施窗口风险。不得用常识补齐缺失的生产数据。

## 工作流程

1. 从用户输入中提取变更单号；缺少编号时再请求用户提供。
2. 首先调用 ChangeInfo MCP 的 `get_change`，取得 `target_ci_ids`、`service_ids`、实施窗口、验证与回退计划；不得自行猜测 CI。
3. 将取得的 CI 标识传给 CMDB MCP：应用发布调用 `get_topology`，防火墙开通还必须调用 `find_network_path`。
4. 将目标及拓扑中的关键 CI 传给 AlertInfo MCP 的 `summarize_alerts`、`search_alerts` 和 `find_related_incidents`，查询变更前近期异常与历史事件。
5. 先用 PerfInfo MCP 的 `list_available_metrics` 确认可用指标，再调用 `get_performance_summary`；需要时用 `query_performance` 查看采样趋势。
6. 使用 ChangeInfo MCP 的 `find_similar_changes` 核对同系统、同类型的历史变更结果。
7. 对交叉来源进行核对；记录冲突、失败调用和缺失数据。
8. 使用 `references/risk-rules.md` 进行可解释的风险分级。
9. 按 `references/output-template.md` 输出报告。

## MCP 边界

- ChangeInfo MCP：变更主数据和历史相似变更；不提供 CMDB、告警或性能事实。
- CMDB MCP：配置项、上下游关系及网络路径；输入 CI 必须来自变更或已返回的拓扑。
- AlertInfo MCP：告警、日志异常和历史生产事件。
- PerfInfo MCP：性能指标目录、窗口汇总和原始采样。

应用发布重点检查应用上下游、部署实例、数据库、中间件、发布前告警、延迟、成功率和历史发布事件。防火墙开通重点检查源/目标安全域、精确 IP/协议/端口、路径设备、策略有效期、会话容量、HA 同步延迟和目标服务当前性能。

模型自主选择和安排工具调用，但在给出最终结论前必须覆盖下列证据域，或明确说明该域无法取得数据：

- 变更内容与实施窗口
- 直接系统与上下游依赖
- 主机、数据库和中间件资源
- 近期告警和错误日志
- 关键性能指标
- 历史类似变更或故障

## 证据规则

- 每项风险依据必须注明来源工具及返回事实。
- 清楚区分“已观测事实”“基于事实的推断”和“数据缺口”。
- 工具无数据、超时或报错不等于系统正常。
- 不得虚构指标值、依赖关系、历史事件或审批状态。
- 数据不足以判断时，输出“暂无法定级”，并列出补数清单；不能为了完成格式而猜测等级。

## 完成条件

最终答案必须包含风险等级、风险依据、影响范围、数据缺口和行动建议。仅输出“高/中/低风险”不算完成。
